# drawr

> Renamed from **Gridfinity Studio**. Same app and API contract, new name and a fresh
> interface design.

A web app to **design Gridfinity storage systems visually and export print-ready STL
files**. You set up a grid (from a drawer size or a unit count), lay out bins on a
2D top-down canvas, tune each bin (footprint, height, dividers, label/scoop/magnet/
screw features), preview the assembled set in 3D, and download a ZIP of every unique
STL.

Geometry is generated by a **Python + build123d (OpenCascade) backend** so the
exported meshes are real parametric BREP solids — verified **watertight and
manifold** — and dimensionally compatible with printed Gridfinity parts.

---

## Architecture

```
drawr/
├── backend/                 # FastAPI + build123d CAD kernel (deploys to Render via Docker)
│   ├── app/
│   │   ├── constants.py     # ★ ALL Gridfinity dimensions, cited & commented
│   │   ├── geometry.py      # parametric bin & baseplate solids -> STL
│   │   ├── schema.py        # Pydantic design-spec contract (+ overlap/bounds/size guards)
│   │   └── main.py          # API + CORS, rate limiting, logging, Sentry
│   ├── tests/               # pytest: watertightness, dimensions, API contract
│   └── Dockerfile
├── frontend/                # React + TypeScript (Vite) — deploys to Vercel
│   ├── src/
│   │   ├── pages/           # Landing, Editor (lazy), NotFound
│   │   ├── components/      # TopBar, Setup, Canvas2D, Palette, Inspector, Preview3D, ExportModal
│   │   ├── store.ts         # Zustand: grid, bins, selection, undo/redo, placement rules
│   │   ├── api.ts           # backend client (VITE_API_BASE)
│   │   └── __tests__/       # Vitest unit tests (store, api, components)
│   ├── e2e/                 # Playwright E2E (backend stubbed)
│   └── vercel.json
├── render.yaml              # Render blueprint for the backend
└── .github/workflows/       # CI: frontend (lint/types/unit/e2e/build) + backend (pytest)
```

**Data flow.** The frontend holds the design as plain JSON (a `DesignSpec`). The
*same* JSON is the API contract:

- `POST /api/grid/compute` — convert a physical drawer size ⇄ a unit count, returning
  both representations plus the leftover margin. The UI never computes grid math
  itself, so the displayed numbers can't drift from what the kernel builds.
- `POST /api/stl/bin` and `POST /api/stl/baseplate` — single watertight STL for a
  part (handy for scripting/debug; also lets you wire a high-fidelity preview if
  wanted).
- `POST /api/export` — builds **every unique part** (identical bins are de-duplicated
  and counted) and returns them as a named ZIP.

**Why build123d (not CadQuery).** Both wrap the same OCP/OpenCascade kernel and both
export watertight STL. build123d was chosen because (1) its algebra mode (`+ - &`,
`loft`, `sweep` as plain functions) makes the stacked-chamfer mating profile and the
per-cell foot array concise and easy to audit against the constants, and (2)
`export_stl` exposes linear/angular tessellation deflection directly, so we can dial
in a fine, manifold mesh. `cq-gridfinity` (CadQuery) was used as a cross-check for the
dimensional constants.

## Running locally

You need **Python 3.11/3.12** (build123d's OCP wheels don't yet cover 3.13+),
**Node 18+**, and [`uv`](https://github.com/astral-sh/uv) (or plain `pip`).

### 1. Backend

```bash
cd backend
uv venv --python 3.12 .venv
VIRTUAL_ENV=.venv uv pip install -r requirements.txt
#   (or: python3.12 -m venv .venv && .venv/bin/pip install -r requirements.txt)

VIRTUAL_ENV=.venv PYTHONPATH=. .venv/bin/python -m uvicorn app.main:app --port 8123 --reload
```

Backend runs on **http://localhost:8123** (interactive docs at `/docs`).

### 2. Frontend

```bash
cd frontend
npm install
npm run dev
```

Open **http://localhost:5173**. Vite proxies `/api` → `:8123`, so the two are
same-origin in dev (no CORS fuss).

## Using it

1. **Setup**: enter your drawer's inner W×D in mm, *or* switch the segmented control
   to a column×row count. A to-scale diagram shows the drawer, the resulting baseplate
   and the margins. *Create grid* opens the editor.
2. **Design**: the toolbar shows a **Setup › Design › Export** breadcrumb, a **2D / 3D**
   segmented control, undo/redo, a **Library** button and the **Export** button. A
   floating tool dock at the bottom of the canvas holds **Select (V)**, **Draw (B)** and
   **Pan (H)**, the footprint presets, and delete. Click the grid to drop the chosen
   preset, or drag across cells to draw any size. Drag bins to move them. Overlaps and
   out-of-bounds placements are blocked with red feedback. The **inspector** on the
   right edits the selected bin: footprint, height (U), compartments (cols×rows), and the
   solid / label / scoop / magnet / screw toggles. On iPad it slides over the canvas.
   Undo/redo supported (⌘Z / ⇧⌘Z).
3. **3D**: switch to 3D (or use the picture-in-picture preview) to orbit the assembled
   baseplate + bins. This is a **live three.js preview** built client-side from
   primitives, so it updates instantly. **Preview filament colors** let you see the
   layout in different plastics. They're preview-only and don't affect the export. The
   watertight CAD geometry is the source of truth for *export* only.
4. **Export**: *Export* opens a part list (with quantities); *Download ZIP* pulls every
   unique STL, sensibly named (e.g. `bin_3x2x6u_c3x1_lab1_sco1_mag1_scr0.stl`,
   `baseplate_7x5.stl`).

**Devices.** The editor works on desktop and iPad (touch: tap to place, drag to draw or
move). On phones the landing page works, and the editor asks for a bigger screen.

## Common drawer presets

Setup's **Choose a common drawer** picker fills in the inside width, depth and height of
popular drawers and cases: IKEA, MUJI, Husky, Milwaukee, U.S. General, L-BOXX,
Systainer³, T-Loc, MakPac, DeWalt TSTAK/ToughSystem, Bisley and more (98 entries in
`frontend/src/drawers/drawers.json`).

- **Every entry cites its source** (`source_url`, `source_kind`: manufacturer / retailer /
  community-measured) and a `confidence`. Medium-confidence entries are shown in amber, and
  the UI always asks you to confirm with a tape measure.
- **Validated on load and in CI.** `validateDrawer` rejects implausible values (anything under
  42 mm or over 1500 mm, which usually means outer dimensions or unconverted inches), bad
  ids and non-https sources. `src/__tests__/drawers.test.ts` fails the build if a shipped
  row is invalid or duplicated.
- **Height-aware.** When the inside height is known, drawr computes the tallest bin that
  clears the drawer (baseplate floor 1.2 mm + 7 mm/U + 1 mm headroom, `src/lib/fit.ts`).
  New bins default to a height that fits, and the inspector, status bar and export sheet
  warn about bins that are too tall.
- **Inches.** The Setup fields accept mm or inches, including fractions like `11 3/4`.
- **Recent sizes.** The last five sizes you used are remembered in this browser.

To add a drawer, append an entry to `drawers.json` with interior dimensions and a source,
then run `npm test`.

## Community model library

The toolbar's **Library** button opens a searchable catalog of community
Gridfinity models (screwdriver holders, battery dispensers, baseplates, generators…).
"Import" drops a model's footprint onto your grid (it reserves the space and links to
the source); on export those models are listed in a **CREDITS.md** rather than
generated — you download each file from its source and follow its license.

**Permissive *generators* become real geometry.** For permissively-licensed generator
entries (MIT/GPL/CC-BY-SA — kennetek's OpenSCAD, cq-gridfinity, etc.), the catalog marks
them `generator: "bin"` and the card shows **Generate bin** instead of Import. That
produces an actual editable, watertight bin from our own build123d engine (dimensions
verified against kennetek), shown with real geometry in 3D and exported as a real STL —
with a provenance note crediting the source. Generated bins also support a new **Solid
(lid/spacer)** option. Bespoke non-generator models (a specific holder) can't be
reproduced and stay link-only.

**We index, we don't rehost.** The catalog is metadata only — title, author,
**verified license**, source link, thumbnail, footprint — because most community
models carry CC licenses (many NonCommercial / ShareAlike) or platform terms that
forbid redistribution. License badges (and a "Non-commercial" flag) are shown on
every card and in the inspector.

The dataset is a standalone, contributable repo —
[**gridfinity-model-catalog**](https://github.com/shariqnaiyer/gridfinity-model-catalog) —
bundled into the app at `frontend/src/catalog/models.json` and refreshable via
`npm run sync:catalog`.

## Dimensional decisions & the mating profile

Every dimension lives in **`backend/app/constants.py`**, each with a source citation:
**[K]** kennetek/gridfinity-rebuilt-openscad (the canonical OpenSCAD parameterization),
**[Z]** Zack Freedman's original Gridfinity Specification, **[C]** cq-gridfinity.

Key verified values:

| Quantity | Value | Source |
|---|---|---|
| Grid pitch | 42.0 mm | K, Z, C |
| Height unit (U) | 7.0 mm | K, Z, C |
| Bin footprint per unit | 41.5 mm (0.25 mm clearance/side) | K, Z |
| Foot/socket mating profile | `0→[0.8,0.8]→[0.8,2.6]→[2.95,4.95]` (chamfer 0.8 / wall 1.8 / chamfer 2.35↑) | K |
| Foot height | 4.95 mm | K |
| Base corner radius | 3.75 mm (baseplate 4.0) | K, Z |
| Magnet hole | Ø6.0 × 2.0 mm | Z |
| Screw hole | Ø3.0 (M3), drilled up the foot | K, Z |
| Hole position | ±13 mm from cell centre (26 mm spacing) | K, Z |
| Stacking lip profile | `0→[0.7,0.7]→[0.7,2.5]→[2.6,4.4]` | K |

The foot reproduces the canonical stair-step so bins **seat into and self-centre** on
the baseplate sockets (the socket is the mirror of the foot). Bounding-box checks
confirm a 1×1×6 bin = 41.50 × 41.50 × 42.00 mm and a 7×5 plate = 294 × 210 mm.

### ⚠️ Assumptions to verify against real parts

These were ambiguous or parametric in the sources and are flagged in `constants.py`:

1. **Stacking lip is simplified.** The bin's top outer edge is filleted to the lip's
   chamfer run, preserving the external envelope and a usable stacking slope, but the
   full inner *receiving pocket* is not modelled. Bins seat on baseplates perfectly;
   bin-on-bin stacking is approximate. (`_add_stacking_lip` in `geometry.py`.)
2. **Magnet hole Ø6.0 / depth 2.0** (the spec, for 6 mm magnets). kennetek prints
   Ø6.5 / 2.4 for press-fit clearance — bump `MAGNET_HOLE_*` if your magnets are tight.
3. **Wall 1.0 mm, floor 1.0 mm, divider 1.2 mm.** Wall/floor are common defaults
   (kennetek's min wall is 0.95); divider is K's `d_div`. Adjust in `constants.py`.
4. **Scoop radius 12 mm** — scoop is parametric in all sources with no fixed value;
   this is a sensible default. Label tab uses K's 36° support angle (community builds
   often cite 45°).
5. **Baseplate**: thin/"lite" style, 4.65 mm recess + 1.2 mm floor (≈5.85 mm total).
   Weighted/magnet-block baseplate variants are not generated.

All exported parts are checked **watertight** (`trimesh.is_watertight` /
`is_winding_consistent` = True; build123d `is_valid` = True).

## Testing

```bash
# Frontend — unit (Vitest + RTL) and end-to-end (Playwright)
cd frontend
npm run test            # store/api/component unit tests
npm run test:e2e        # full editor flows; backend is stubbed at the network layer
npm run typecheck       # tsc
npm run lint

# Backend — pytest (geometry watertightness, dimensions, API contract)
cd backend
pip install -r requirements-dev.txt
pytest
```

The E2E suite stubs `/api/*` (the 3D preview is client-side), so it needs no CAD
backend — which keeps CI fast. Backend correctness (watertight meshes, exact
dimensions, validation, export bundling/dedup) is covered by the pytest job.
Both run in GitHub Actions on every push/PR (`.github/workflows/`).

## Deployment

drawr runs as **one Vercel project with two [Services](https://vercel.com/docs/services)**
(root `vercel.json`), live at **https://drawr.ca**:

- `web`: the Vite frontend (`frontend/`), served as static files with an SPA fallback.
- `api`: the FastAPI + build123d backend (`backend/`), built from `backend/Dockerfile.vercel`
  as a container image and routed at `/api/*`.

The two share one origin, so there's no CORS configuration and no `VITE_API_BASE`. The
container scales to zero after about 5 minutes idle, so the first request after a quiet
period takes about 7 s while it starts. `TRUST_PROXY_HEADERS=1` (set in
`Dockerfile.vercel`) makes rate limiting key on the visitor's real IP, which Vercel
reports in `x-real-ip` / `x-forwarded-for`.

```bash
vercel deploy          # preview
vercel deploy --prod   # production (drawr.ca)
```

**DNS** is on Cloudflare: `drawr.ca` has an `A` record to Vercel (`76.76.21.21`) and
`www.drawr.ca` has a `CNAME` to Vercel. Both are **DNS only** (grey cloud), so Vercel
issues and renews the TLS certificate. `www` 308-redirects to the apex.

**Alternative:** `render.yaml` still describes a standalone Render deployment of the
backend. If you use it, set `VITE_API_BASE` on the frontend and `ALLOWED_ORIGINS` on
the backend.

## Tech

- **Backend**: Python, build123d (OpenCascade/OCP), FastAPI, Uvicorn.
- **Frontend**: React + TypeScript, Vite, Zustand, three.js / @react-three/fiber +
  drei (3D), lucide-react (icons). Type is the system SF stack (SF Pro / SF Mono on
  Apple devices) with Inter as the fallback elsewhere — no web font loads on Apple hardware.
